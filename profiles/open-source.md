# Profile: open source

Libraries, tools and frameworks with a public repository and community.

## Typical pillars

| Pillar | Tier | Shape |
| --- | --- | --- |
| Release | Core | Version, the one change that matters most, upgrade note, link to notes |
| Tip | Core | One API or option, with a short code sample as an image or link |
| Contributors | Optional | Thanks to contributors who agreed to be named |
| Roadmap / RFC | Optional | A decision open for feedback, with the discussion link |

## Source adapter

Releases and tags, merged pull requests, closed milestones and discussions for the period from the forge's API. Contributor handles only from the project's own records and only when they agreed to be mentioned.

## Extra checks worth adding

- Version numbers and breaking-change notes match the release.
- Code samples compile against the released version.
- Mentions of people are opt-in; never tag automatically.
- Links go to the project's own repository or docs.

## Risks

Audiences are expert and allergic to marketing. Prefer Mastodon, Bluesky and LinkedIn tone; keep hashtags minimal.
