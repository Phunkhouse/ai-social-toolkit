# Profile: product or SaaS

Projects that ship software to users: apps, web services, tools.

## Typical pillars

| Pillar | Tier | Shape |
| --- | --- | --- |
| What's new | Core | One shipped change, what it lets the user do, a screenshot |
| How to | Core | One task done better with the product, in three steps or fewer |
| Behind the build | Optional | A decision, a number or a lesson from building it |
| Use case | Optional | A real (permitted) user story, or a typical one marked as such |

## Source adapter

The changelog, release notes or merged pull requests for the period (titles, dates, links, labels such as `user-facing`), plus the owner's list of what to highlight. `validUntil` is empty; a feature behind a flag is not posted.

## Extra checks worth adding

- A feature named in copy is released to the audience the post reaches (not behind a flag or beta-only, unless the post says so).
- Screenshots contain no personal or customer data.
- No claims about competitors; no performance numbers without a measurement in the package.
- Prices and plans only from the project's own pricing page.

## Risks

Hype is the main failure: release posts drift into "excited to announce". The English pack's AI-cliché rules matter most here.
